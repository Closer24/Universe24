# Computational-field curvature probe

This experiment asks one narrow question: does the existing Universe24 computation-field and local-cost machinery produce a curvature-like observable without inserting a gravity, geodesic or turning formula?

The probe deliberately separates three clocks that are easy to confuse:

1. **Global scheduler tick** — the coordinate-like time used to order events.
2. **Carrier local clock** — a stationary `local_clock` increments `clock_count` only when its own local cycle completes. Its `measured_cycle_cost` records the operation cost that sets that cycle's delay.
3. **Spatial-field clock** — configured spatial fields forward on the independent fixed `link_ticks` clock.

## Geometry

The default world is open and three-dimensional with shape `(25,17,7)`. The stationary mass source is at `(12,8,3)`. Two clock records sit at `(12,10,3)` and `(12,14,3)`, at Manhattan distances 2 and 6 from the source. A massless carrier probe travels in `+X` along `(y,z)=(12,4)`. A separate spatial wave travels in `+X` along `(y,z)=(12,2)`. Both pass the source at the same Manhattan impact distance 5. The detector plane is `x=21`.

The fields are:

- `mass`: stationary source inventory.
- `computation_field`: scalar outward field emitted by the mass source.
- `ray_token` and `direction`: a whole-record massless carrier probe.
- `clock_count`: completed local cycles of each stationary clock.
- `measured_cycle_cost`: the already-metered cost that drives each clock's local delay.
- `wave`: an independently transported local spatial field, streamed through `+X` with no turning rule.

No spatial coupling, force, geodesic correction or explicit trajectory rotation is configured. Therefore any lateral path change would have to arise from existing scheduling/transport behavior rather than a supplied gravity law.

## Measurements

`measure.py` runs five worlds and records an HTML playback for every run:

| Case | Mass | Normal local budget |
| --- | ---: | ---: |
| `control` | 0 | 32 |
| `weak_mass` | 64 | 32 |
| `strong_mass` | 512 | 32 |
| `strong_mass_tight_budget` | 512 | 16 |
| `strong_mass_loose_budget` | 512 | 64 |

For every tick it samples the computation-field value and spatial processing cost at the near clock, far clock and ray impact region. It records both local clock counters and their reported cycle cost, the carrier ray's sent/received positions, the spatial wave's resident/in-flight positions and both detector arrival times.

The independent readouts are:

- **Carrier coordinate delay:** detector progress/arrival of `massless_ray` relative to the zero-mass control.
- **Spatial-wave coordinate delay:** detector arrival tick of `wave` relative to control.
- **Path bending:** maximum lateral displacement from each probe's original `(y,z)` line.
- **Clock-rate gradient:** near/far local-cycle timing, with a separate 64-tick run beginning its established-field analysis at tick 32.
- **Mass scaling:** progress of the weak and strong carrier at equal global time and unchanged computation budget.
- **Budget sensitivity:** the same strong-mass world at local budgets 16, 32 and 64.
- **Local causal link time:** every carrier `sent` event retains its explicit `arrival_tick - tick`; this distinguishes waiting at a node from slowing a link in transit.

## Observed result

The successful measured run was GitHub Actions run `34701173980` under Python 3.14.7. The five 28-tick worlds and the 64-tick established-field world all completed, and every world generated an HTML playback.

The zero-mass control sends both probes to detector `x=21` at tick 20. Both paths remain exactly on their configured lines and every carrier link traversal is exactly one tick.

With mass 64 and budget 32, the spatial wave still arrives at tick 20. The carrier has not reached the detector by tick 28 and has reached only `x=16`. Its path has zero lateral deflection. The near clock completes 5 cycles by tick 28 while the far clock, which this weaker integer field does not reach at the selected resolution, completes all 28.

With mass 512 and budget 32, the spatial wave again arrives at tick 20 and has zero lateral deflection. The carrier still has not reached the detector by tick 64; by then it has reached only `x=15`. Its lateral deflection is zero and every actual link traversal remains exactly one tick. The delay is therefore waiting at cells, not slower link propagation.

One representative strong-mass carrier cycle starts at `x=9` on tick 8 with measured cost 244. For budget 32 the existing timing law makes the local cycle period 8 ticks: the record waits locally through tick 15 and then crosses the next link in one tick, arriving at tick 16. With the same physical configuration but budget 16 the wait is longer; with budget 64 it is shorter. This confirms that the observed carrier delay is generated by the simulator's local computation scheduling.

The long established-field run shows a persistent radial clock gradient. From tick 32 onward the near clock sees computation-field values 28–32 and every sampled local cycle has period 7. The far clock sees values 0–4; it normally has period 1 and changes to period 7 only on ticks where a computation-field pulse is locally processed. Thus the near clock continues to run slower after the field has already had time to reach the farther radius. This is not merely an initial propagation-front effect.

The result is therefore **partial curvature-like behavior, not full curvature**:

- present: local time dilation/clock-rate gradient;
- present: coordinate-time delay of a massless carrier while each local link remains one tick;
- present: stronger mass produces less carrier progress at the same global time in the tested integer configuration;
- absent: spatial-wave delay;
- absent: carrier bending;
- absent: spatial-wave bending.

The full-curvature acceptance condition therefore fails. The simulator currently gives the computation field to carrier scheduling but not to the spatial-field forwarding clock. That representation mismatch is the main missing bridge: a carrier can experience computation-induced time delay while a wave encoded as a spatial field ignores it.

The established computation field is also discrete and pulsed at the farther radius: its value there alternates between 0 and 4 rather than forming a smooth static potential. The observed gradient is consequently a deterministic integer duty-cycle effect at this resolution. Any comparison with a continuum gravitational metric must first demonstrate convergence under increased spatial/value resolution rather than assume it.

## Acceptance rule

A full curvature-like signature is not declared merely because a carrier waits near an active field. For this probe it requires all of the following without adding a gravity-specific update:

1. positive carrier travel-time delay;
2. positive spatial-wave travel-time delay;
3. lateral carrier bending;
4. lateral spatial-wave bending;
5. a persistent near/far local-clock rate gradient after both sites are inside the established field; and
6. a stronger effect for the stronger mass source at fixed numerical budget.

A partial result is still useful evidence about the current simulator. In particular, a carrier delay with unchanged one-link transit is a local computation-delay effect; it is not by itself spacetime curvature. A spatial wave that ignores that delay demonstrates a clock-composition gap that must be resolved before identifying the result with gravitational light propagation.
