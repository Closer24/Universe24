# אמינות ושחזור — U24-RELIABILITY-v1

[English](RELIABILITY.md). זהו מימוש תוכנית האמינות שאושרה, בענף נפרד המבוסס
ישירות על `ed1556e202eb0f3cc60342c75d44012c2eeb71c3`, ללא תלות במיזוג PR #1.
לא השתנה קובץ תחת `universe24/`, לא השתנו הצימודים או סמנטיקת הקליקים,
ולא נוספה פעולת התפתחות. כלי המחקר אינם חלק מהדינמיקה. אין מיזוג אוטומטי
ואין שינוי בהגדרות ההגנה על המאגר.

## מה נבדק

השאלה היא האם מימוש נפרד של המפרט נותן אותו מצב מלא, והאם אפשר לשחזר את
הראיות. הצלחה היא ראיה חישובית לתקינות בתחום מוגדר, ולא אימות פיזיקלי.
ההוכחה להפיכות וזהויות המאזן נשארות טענות מתמטיות נפרדות מבדיקות סופיות.

בגרסת הבסיס יש 15 שיטות בדיקה; נוספו 28, ובסך הכול 43. אין לזהות מספר זה
עם מספר התרחישים שבתוכן. הדיווח ההיסטורי על ״32 בדיקות הפיכות נוספות״
לא זוהה כחבילת ניסוי מלאה ולכן לא אומץ כמניין מאומת. המשך הרצה מ־checkpoint
מקבל כעת בדיקות רגרסיה דרך קבצים ופקודות אמיתיים.

## מימוש ההשוואה העצמאי

`research/reference/` אינו מייבא את המנוע, את החבורה או את טבלאות הצימוד
שלו. הוא משתמש בכפל מטריצות מדויק בגודל 4×4, מעל שברים רציונליים עם √2.
קבוצה מפורשת של 48 מטריצות נבדקת מול סגירת היוצרים. סדר יצירת התוויות
נבנה בנפרד לפי מוסכמת המפרט, עם עוגנים לזהות, ליוצרים ולאיבר המרכזי.
הסיבובים, הניתוב והסימנים נגזרים מחדש. ההתפתחות משתמשת במצב צפוף מלא
ובאיסוף קלטים, בניגוד לפיזור הדליל במנוע.

שני המימושים עדיין חולקים מפרט וחשבון שלמים של Python. לכן הסכמה ביניהם
אינה שוללת כל טעות רעיונית משותפת ואינה מוכיחה שהמפרט מתאר את הטבע.

אי־התאמה בין המימושים שומרת את ההכנה המקורית, הצעד והכתובת הראשונים,
הערך הצפוי והערך שהתקבל ופקודת שחזור. אין כרגע מזעור אוטומטי של דוגמה
נגדית. כשלי בדיקות אחרים נשמרים ביומן עם הקשר המקרה ופרטי הכשל.

תקציב שלב 96 ההכנות הוא 300 שניות מעבד. תקציב חבילת האימות כולה הוא
600 שניות זמן קיר. חריגה מסומנת כבלתי מכרעת, לא כהפרכה של אפשרות מתמטית.

## שחזור מסביבת מקור נקייה

מתיקיית המאגר, עם Python 3.11 או 3.12:

```bash
python -m research.reproducibility.run --output runs/first
python -m research.reproducibility.run --output runs/second --skip-tests
python -m research.reproducibility.run --compare runs/first runs/second --compare-experiments
```

הפקודה הראשונה מריצה את כל הבדיקות, הכנות הדוגמה, הדוגמה הנגדית לשימור Q
ותעודת השיקופים. השנייה חוזרת על הניסויים בלבד ומסומנת במפורש `bundle_only`.
ההשוואה מחייבת זהות של קובצי המקור, הקלטים והתוצאות; האפשרות
`--compare-experiments` משמיטה רק את ההבדל בהיקף ובביצוע חבילת הבדיקות.

תיקיית פלט קיימת אינה נדרסת. סביבת מקור לא נקייה נדחית, אלא אם נבחר
במפורש `--allow-dirty` להרצה חקרנית, והדבר נרשם. טביעות קובצי המקור
נבדקות גם בסיום; שינוי קוד בזמן הבדיקה פוסל את קיבוע הגרסה. commit של
סביבת המחקר ו־commit של מנוע הבסיס נשמרים כשדות נפרדים.

אפשר להריץ בנפרד גם את הפקודות המקוריות:

```bash
python -m unittest discover -s tests -v
python -m universe24 --config examples/impulse.json --audit
python -m universe24 --config examples/signed_impulse.json --audit
```

## מבנה הראיות

- `protocol.json`: השאלה, הקריאה, המפרט, ההכנות, התקציב וקריטריון ההצלחה.
- `manifest.json`: גרסאות מקור, טביעות קבצים וצימודים, סביבת הרצה ופקודה.
- `result.json`: הפרדה בין מצב הביצוע, תקינות המימוש ותוצאת הטענה המדעית.
- `runtime.json`: זמני הריצה, שאינם חלק מההשוואה הדטרמיניסטית.
- `cases/<id>/input.json`: הקלט המלא; `initial.json` ו־`final.json`: נקודות שחזור מלאות.
- `trace.jsonl`: צעדים, טביעת מצב מלא, Q ומניין אירועים אריתמטיים.
- יומני בדיקות ושיקופים, ודוגמאות נגדיות במקרה של אי־התאמה.

הסכמות ממוספרות בגרסה. המאמת תומך במפורש בתת־הקבוצה הנדרשת של JSON
Schema ואינו מתיימר לממש את התקן כולו. הוא דוחה מזהי מקרים כפולים ותוצאות
הצלחה סותרות או ריקות. קריאת JSON ו־JSONL דוחה מפתחות כפולים וקבועים
שאינם מספרים סופיים. טביעות מצב אינן תחליף להכנה המלאה ולמחולל המשוחזר.

תוצאה מדעית שלילית צפויה אינה כשל תוכנה. שינוי בתוצאה הצפויה, בסמנטיקת
הקריאה או בקיבוע המקור מחייב פרוטוקול חדש שנבדק; אין עדכון אוטומטי של
״תוצאות נכונות״.

## ממצאים, כשלים וגבולות

שתי הכנות ה־impulse המסוימות, עם L=9 ומקור `(0,2,2)` בערוץ 0, חוזרות
למצב המלא הראשון ב־t=6; הכנת השעון ב־L=7 חוזרת ב־t=4. אין בכך ראיה
לגל חופשי מתמשך. בכל ניסוי impulse נרשמים 28 אירועים אריתמטיים ב־12
צעדים; השעון אינו מפיק אירוע כזה ב־16 צעדים לפי המשמר הקיים. רישום אפס
כאן נמדד עם התצפית מופעלת ואינו אומר שהמצב קפוא.

בצימוד `(1,-1,1)`, עירור יחיד `(0,1,2)` ב־L=3 משנה את Q ב־‎−8, עם היפוך
מדויק. זו דוגמה נגדית לשימור אוניברסלי של אותו חשבון, ולא זיהוי של אנרגיה.

בביקורת כלי המחקר החדשים נמצאו ותוקנו השמטת קובצי שיקוף מטביעות המקור,
קריאת JSONL שהתירה מפתחות כפולים, ואפשרות לאשר מזהי מקרים כפולים או
תוצאת הצלחה סותרת. שום תיקון לא חייב שינוי במנוע.

בדיקת שגיאה מכוונת ראשונית החליפה את שני הקלטים הנגדיים בכל זוג. מכיוון
שמשקליהם שווים, זו רק החלפת סדר הסכום; לכן לא הייתה שגיאה לגלות. המקרה
נשמר כביקורת שקילות. שגיאת כיוון אמיתית בפורט יחיד נבדקת בנפרד ומתגלה.

בחבילת הפיתוח המקומית שהושלמה לא נמצאה אי־התאמה במנוע. ראיות הקבלה
הסופיות מסביבת מקור נקייה ומ־CI יצורפו ל־PR ולדוח הקבלה. לא הוסקו חלקיקים,
זמן פיזיקלי, מדידה קוונטית, חוק Born, שימור אנרגיה או כבידה. תוצאת המוליך
הזמני שב־PR #1 אינה תנאי קבלה לענף הזה.

## CI והחלטת קבלה

ה־workflow פועל ב־PR, בעדכוני ענף המחקר ובהפעלה ידנית, עם Python 3.11
ו־3.12, הרשאות קריאה ופעולות המקובעות ל־SHA מלא. הוא שומר פלט וכשלים
ל־30 יום. זהו אחסון זמני: ראיות מאומצות ודוגמאות נגדיות צריכות להישמר
ב־commit מחקרי שנבדק. אין מיזוג או שינוי בהגנות המאגר.

קבלה מחייבת את כל הבדיקות, ליבה ללא שינוי, השוואת מצב מלא, שחזור אירועים
ונקודות שמירה, תוצאת Q השלילית הצפויה, התאמת תעודת השיקופים ושחזור
דטרמיניסטי. אי־התאמה בלתי מוסברת חוסמת קבלה. בחירת כיוון המחקר הבא נשארת
בידי יוזם הפרויקט.
