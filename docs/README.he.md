# Universe24 — מדריך למאגר

**Universe24 הוא מנוע מחקרי של אוטומט תאי הפיך; הוא אינו תאוריה פיזיקלית מוכחת.** מטרתו לבדוק אילו תבניות, שעונים, אותות ואירועים יכולים להיווצר מתוך חוק מקומי אחד.

[חזרה ל־README](../README.md) · [הנוסחאות](MODEL.md) · [הניסויים](EXPERIMENTS.md) · [מגבלות המחקר](RESEARCH_STATUS.md)

## מה קבוע?

- המרחב הוא **קובייה מחזורית סגורה**: צלע יחידה `L >= 3`, עם `L³` צמתים. יציאה מפאה אחת מחזירה דרך הפאה הנגדית.
- בכל אתר **צומת בסיסית אחת ולוח אחד**, שמכיל **48 ערוצים** המסומנים לפי החבורה `2O`.
- בכל ערוץ שני מונים שלמים `a,b` ושארית `r=0..5`: בסך הכול **96 מונים שלמים ו־48 שאריות לכל צומת**.
- כל ערוץ מקבל **בדיוק שישה קלטים מרחביים**, אחד בכל כיוון `+x,-x,+y,-y,+z,-z`. **אין קישורים פנימיים ואין לוח B.**
- הצימודים נגזרים מאותה חבורה. הטנזור יכול להכיל `-1,0,+1`: האפס מסמן שערוץ מסוים אינו מחובר לערוץ שולח מסוים, אך **בכל כיוון יש תמיד חיבור יחיד שאינו אפס**.
- נבחרים פעם אחת שלושה סימני גוף, כגון `[1,1,1]` או `[1,-1,1]`, והם נשארים קבועים כל הריצה.
- **Rule3 בלבד** משנה את המצב. המונה `a` הוא המצב הקודם, `b` המצב הנוכחי, ו־`r` שומר את שארית החלוקה.

העדכון לכל ערוץ הוא:

```python
ell, r_next = divmod(2 * six_signed_spatial_inputs_sum + r, 6)
a_next = b
b_next = ell - a
```

כל הצמתים מחושבים מאותו מצב ישן. **אין בקוד "חוק לאטום", "חוק לגלאי", פקודת ביטול, שינוי צימודים בזמן אמת או שעון פנימי שמפעיל את Rule3.**

## איך מריצים?

יש צורך ב־Python 3.11 ומעלה. אין תלות בספריות נוספות להרצה מהמאגר.

```bash
python -m unittest discover -s tests -v
python -m universe24 --config examples/impulse.json --audit
python -m universe24 --config examples/signed_impulse.json --audit --events events.jsonl --output final.json
python -m universe24 --resume final.json --steps 10 --audit
```

קבצי `events.jsonl` ו־`final.json` חייבים להיות **שמות חדשים** שאינם קיימים. `final.json` שומר את מצב המערכת המלא להמשך ריצה קדימה; יומן אירועים לא מאפשר שחזור כזה.

## מה מותר לאתחל?

`side` — צלע הקובייה; `coupling_signs` — שלושת הסימנים הקבועים; `background` — מצב רקע קבוע (ברירת מחדל `[0,0,2]`); `seed_changes` — רשימת שינויים נקודתיים מתוך הרקע; `steps` — מספר צעדי הדמיה. השינויים בזרע הם רק לפני הריצה.

קובץ לדוגמה:

```json
{
  "side": 9,
  "coupling_signs": [1, 1, 1],
  "background": [0, 0, 2],
  "seed_changes": [
    {"position": [4, 4, 4], "channel": 0, "state": [0, 2, 2]}
  ],
  "steps": 12
}
```

זוהי **הפרעה התחלתית**, ולא הגדרה של פוטון או חלקיק.

## שלושת סוגי הקליקים

השארית מתפרקת ל־`r=2θ+ε`, כאשר `θ∈{0,1,2}` והזוגיות `ε` נשמרת. כלל 3 מקיים `θ'=(θ+u) mod 3`. לכן אירוע חשבוני מקבל אחת משלוש מחלקות `C0,C1,C2`. בתוכנה אירוע נרשם רק כשמנת החלוקה אינה אפס והשלשה המקומית משתנה.

**הקליקים נרשמים מחוץ למערכת בלבד.** התצפית אינה משנה ערכים או מאשרת מימוש. `C2` כשלעצמו אינו בחירה אמיתית: גם שעון רגיל יכול להפיק אותו.

## שעונים, זמן, מראות ושימור

שעון הוא **תבנית מחזורית שמתפתחת מתוך המונים**, לא מנגנון נוסף שגורם לצומת להתעדכן. צעדי החישוב של התוכנה הם אינדקס השוואה, לא הגדרה מוכחת של זמן פיזיקלי.

סימני הצימוד עשויים לשנות מחזורים והתאבכות, אך לא הוכחה מהם הפרת מראה פיזיקלית. החשבון האלגברי החתום `Q` אינו אנרגיה פיזיקלית, ובטנזור חתום מתוסכל גם אינו נשמר בדרך כלל. שימור תנע זוויתי פיזיקלי, כלל בורן, קליק גלאי בלעדי ואותות ביטול אוטונומיים **עדיין לא הוכחו**.

## איך מוסיפים ניסוי?

מוסיפים קובץ JSON חדש לתיקיית `examples/`, משנים רק את הזרע, צלע הקובייה, הסימנים הקבועים ומספר הצעדים. **לא מוסיפים קוד שמחליף את Rule3**. מצבי הכנה מיוחדים של גלאים ושעונים נחשבים חלק מהזרע בלבד.

לפני שינויים במנוע יש לקרוא את [AGENTS.md](../AGENTS.md) ואת [CONTRIBUTING.md](../CONTRIBUTING.md).
