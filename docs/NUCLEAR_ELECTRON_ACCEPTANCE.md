# Nuclear and electron acceptance contracts

This document owns the executable acceptance requirements exposed by the
nuclear/electron audit. It does not select missing physical laws. The central
[register-theory specification](https://docs.google.com/document/d/1jPBMb-1BoCH8Qo6y5E-j0H0ANWzbHmkO9l-9t2pxSOQ/edit)
defines deterministic property-selected strong/weak Node interactions, a strong
long-residence hypothesis and causal computation-field emission. Its paragraphs
P00125-P00129 and P00168 in the 2026-09-16 reviewed snapshot distinguish that
accepted structure from unspecified numerical family operations. Paragraph IDs
identify that snapshot, not stable Google Docs anchors.

Every requirement below is an acceptance target unless identified as measured
evidence. Follow [physical-feature ownership](PHYSICAL_FEATURES.md),
[local conservation](LOCAL_CONSERVATION.md) and the current
[Node implementation contract](NODE_VECTOR_PROCESSOR.md). No passing inventory
ledger or catalog entry closes an absent physical law.

## Required profile declaration

Before implementation, the theoretical physicist and mathematician must provide
a named numerical profile with this complete input/output contract:

| Item | Required declaration |
| --- | --- |
| State | Scalar/Vector meanings, units, integer scales and bounds; participant IDs, ownership and fixed local capacities |
| Operation | Exact property eligibility and a bounded deterministic local operator on admitted participants and arrived Port values; names cannot select physics |
| Time | Local-cycle meaning, six output-delay maps, fixed neighboring transit H, completion/release condition and counter bounds |
| Field | Exact ray amplitude/direction and emission schedule, funding and recoil owners, remainders, and whether a pending operation can emit |
| Readouts | Actual energy, momentum and relevant charges of participants, fields, retained outputs and Link packets; external sources separately identified |
| Measurement | Actual Detector encounter, coherent operation and any Detector-owned probability/ticket law; all ordinary evolution consumes zero tickets |
| Predictions | Independently calculated finite expected traces, tolerance/encoding error, boundary horizon and declared failure conditions fixed before execution |

Unspecified cells are OPEN. A catalog mass, an elapsed host time or a prescribed
output location cannot silently fill them. The developer implements the completed
contract; the experimental physicist independently fixes controls and expected
measurements; the architecture reviewer checks composition and bounded ownership.

## Weak conversion and physical kinematics

Tracking: [weak profile issue #150](https://github.com/Closer24/Universe24/issues/150).
**Next owner: theoretical physicist and mathematician for the weak profile;**
the generic conversion developer implements its eligibility/kinematic guards.
The experimental physicist owns lifetime/spectrum predictions and measurement.

The existing `configured-lepton-reactions-v1` gallery conserves its declared
component sums. With the two configured auxiliary `vacuum_slot` records, its
beta conversion occurs at ticks 4 and 5. Without them, the original audit saw
zero conversions through tick 11. This tests configured local replacement,
not a lifetime or spontaneous weak-transition law.

The beta electron has E = 7 and p = (7,0,0), in units of 0.1 MeV and 0.1 MeV/c.
Thus E squared minus the squared momentum is exactly zero. The gallery now
reports this failed necessary massive-particle condition separately from
balanced accounting; a positive value alone never receives a physical pass.
The passive screen includes saved resident, held-output and in-flight owners.
It does not modify the fixture, insert rest energy or reinterpret E as kinetic
energy. The full reaction still needs a physical kinematics repair.

[NIST's neutron beta-decay review](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=902353)
describes three outgoing products, electron rest mass, continuous product
energies and decay/correlation observables. These are validation targets. A
one-tick intermediate record is not a measured W-boson lifetime.

| Case | Required acceptance |
| --- | --- |
| W1 allowed/forbidden | Exact property-selected admitted channel and a forbidden control, including insufficient available energy; rejected work leaves all local owners unchanged |
| W2 simultaneous accounting | Full pre/post energy, momentum and charge readouts, including all products and reservoirs, balance per actual committed event; passing total sums cannot excuse an invalid individual product |
| W3 massive product | Define units, exact mass encoding and any error interval first. Require E_i > 0 and independently evaluate E_i squared minus c squared times p_i dot p_i against m_i squared c to the fourth for each asymptotic product. Reject negative-energy products and the present zero-shell electron; reject an unphysical recoil even when pair sums balance |
| W4 weak dynamics | Supply deterministic unmeasured channel evolution, its physical time map and an actual Detector instrument. Derive survival/lifetime and product-energy/angular statistics without autonomous ordinary draws. A deterministic waiting timer or placed slot does not pass |
| W5 replay and limits | No extra conversion, stock debit, emission or ticket on duplicate event observation; bounded retention and integer overflow rejection are explicit |

The mass-shell benchmark is a read-only acceptance condition; it is not a
continuum update formula to insert into the generic engine. The weak operator,
mass/energy encoding, lifetime and spectrum remain OPEN.

## Electron localization and frequency

Tracking: [electron profile issue #151](https://github.com/Closer24/Universe24/issues/151).
**Next owner: theoretical physicist and mathematician for a bound-state profile;
generic developer after the profile is defined; experimental physicist for the
independent localization/frequency measurement.** A charged classical proxy
does not acquire a phase law from its particle name.

The charged proxy now explicitly selects existing balanced Port routing under
`signed-ray-charge-interaction-probe-v2`. With momentum (-400,800,0), a free
one-hop-per-tick carrier first dispatches +Y, -X, +Y. The former cyclic route
starts with a block of -X departures and hides the tangential component over a
short run. The generic cyclic API is unchanged; historical v1 results keep
their original identity. Balanced routing does not supply an attractive law,
an energy closure, an orbit or a phase frequency.

Original audited evidence at source a7b0bf7, with balanced routing selected:
the 41-cubed, 96-tick charge-proxy world retained the electron inside the domain,
but its squared separation grew from 9 to 137 with no return of position/momentum
or the chosen section. The translated 21-cubed trace agrees through tick 89;
the smaller world's boundary escape at tick 90 is not asymptotic unbinding.
The selected proxy stores mass, charge and momentum, with no electron phase law
or physical tick-to-time map. Its energy/angular momentum were not validated.

| Case | Required acceptance |
| --- | --- |
| E1 routing baseline | With no coupling, fixed momentum, declared rate and all six orientations, compare independent Port quotas and unchanged momentum. Include large common weight scaling and zero momentum |
| E2 local field | Keep the existing ray mechanism: six-neighbor hops, exact H, no pre-arrival response, and isolated-emitter self-exclusion in its declared scope. Account for sources and all carried/reaction inventory |
| E3 localization | Define a physical state, center, fixed radius/readout, horizon and boundary guard before running. Measure localized support or bounded separation, and a larger-domain common causal prefix. Merely remaining inside a larger box cannot pass |

| E5 phase and frequency | Supply an actual amplitude/internal phase representation, local evolution/coupling operator and a relative-phase or Detector observable with a physical time map. Separate this observable from trajectory-return rate and playback frames |
| E6 stability and closure | Predeclare perturbed initial states and full energy/momentum readouts, including fields and sources. Demonstrate the predicted stability response without tuning the law after inspecting the trajectory |
| E7 Detector composition | Run the same admitted state with and without the actual Detector, requiring zero tickets without it and the defined PASS/RETURN/no-redraw behavior with it; an unsupported composition is not a pass |

These cases do not assume a classical planetary orbit. The previously observed
unlocalized trajectory is a counterexample for one configured initial state,
not proof that every possible bound-state profile is impossible.
