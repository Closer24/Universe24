# Central model specification and document ownership

The [existing unified Node schema](https://docs.google.com/document/d/1jPBMb-1BoCH8Qo6y5E-j0H0ANWzbHmkO9l-9t2pxSOQ/edit) is the single authoritative
home for model definitions. Its Model specification tab contains five sections;
its Evidence and references tab separates old results and source pointers.
[Highlights](https://docs.google.com/document/d/1IkhSyqZZMBSgbJV-PMMwcXG0D_Rlfg4FrLy2jXBMUSs/edit) is a short summary and navigation document,
not a second set of laws. Latest explicit user decisions take precedence.

| Central section | Owns |
| --- | --- |
| 1. Node state and ray form | NodeState, complete event properties/identity, six-neighbor topology, fixed local channel/resource limits, foundational postulates and representation |
| 2. Generic operations at the Node | Local participant snapshots, operation/engine/data separation, transactions, symmetry and exact arithmetic requirements |
| 3. Couplings, fields and timing | Ray-form field transport, funded exchange/emission, computation-field delay, mass/phase/time distinctions and physical-sector reference examples |
| 4. Defined quantum action and Detector | Existing event-space quantum action, committed-event no-redraw/no-re-emission, named pair/general profiles, external Detector exchange and causal history/return boundaries |
| 5. Acceptance and open decisions | Node/Link input-output-failure cases, directional displacement/contact checks, explicit candidate choices, integration gaps and developer handoff |

Generic physical operations execute **at the Node**. A separate operations
package is code ownership, not another physical location. There is no fixed
internal register graph or count.

Historical private-register experiments remain history. Storage registers,
quantum algebra registers and BondRegistry retain their separate meanings.

## Reconciliation and status discipline

- **Defined model action:** preserve it; do not call it OPEN because a particular
  profile cannot execute or compose it.
- **Named candidate:** explicit proposed operator, encoding or lifecycle, subject
  to its declared review/scope; no silent universal default.
- **Integration gap:** missing adapter, supported composition or bounded lifecycle;
  report separately from an undefined physical law.
- **Verified result:** identify source, profile, input and completed evidence;
  never infer it from documentation or a displayed animation.

The shared quantum action is already defined. Same-event replay never draws
or physically emits again; a distinct contact may create a new event. Released
BondRegistry pair-key reuse is a bounded profile-lifecycle gap, not permission
to redraw a completed event. Immutable origin/history persistence already exists;
the local lookup/stop/retention rule for a moving event's return notice remains
separate and incomplete. An event ID alone is not a local routing algorithm.

The central section 1 owns the cabinet/channel resource target, moving-event
identity and directional displacement requirement. Section 5 owns its acceptance.
Refer there instead of copying another version of the storage/work or routing
contract into implementation summaries.

## Acceptance for documentation changes

Inputs: the latest user decisions, central model revision and named profile
sources. Expected: each definition has one designated owner; summaries point to
it; no accepted action is relabeled undecided; candidates and old evidence are
marked. Preserve native document links, meaningful structure and all unique
accepted constraints when moving content. Fail on lost content, contradictory
authority, an unlabeled physical choice, claimed tests without evidence or an
implementation change hidden as documentation. Runtime code and tests remain
developer-owned. No workflow Skill change is needed: the existing shared
workflow already requires one owner and source-grounded handoffs.
