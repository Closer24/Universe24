# מה בודקים ומה מצפים לקבל

החישובים המשותפים נמצאים ברכיבים כלליים. המודל שלנו בוחר משקלים, מקור,
כלל פנייה ומדיניות פעילות, ומחבר את התוצאות למצב התא והחלקיק. תרחיש מגדיר
תנאי התחלה; המנוע מנהל זמן, שכנים ותפוסה; המדידות קוראות את התוצאה.

## בדיקות לפי אחריות

| קובץ בדיקה | האחריות שנבדקת | מה מצפים |
| --- | --- | --- |
| `test_integer_contract.py` | חשבון שלמים וגבולות | מנה ושארית מדויקות גם במספרים שליליים; גלישה נעצרת לפני שימוש בתוצאה |
| `test_lattice.py` | גאומטריה מחזורית | אותו סדר של שישה שכנים בכל הקריאות והמעברים, כולל בגבול המרחב |
| `test_scalar_field.py` | חישוב שדה כללי | משקלים שונים, ערכים חתומים ושאריות מפיקים תוצאה מספרית ידועה |
| `test_field_policies.py` | מקור, טווח ערכים ופעילות | עוצמת המקור נגזרת מהספירה; איפוס ושאלת המשך העדכון נבדקים בנפרד |
| `test_turning.py` | תגובה כללית לווקטור | כל כלל כיוון משתמש באותו חישוב דחף; כל תוספת לחלקיק נגרעת מהשדה |
| `test_movement.py` | תקציב תנועה ובחירת ציר | תנע וכיוון נשמרים ללא השפעת שדה; התקציב קובע מתי מתבצע צעד אחד |
| `test_current_field.py` | החיבור למודל שלנו | מקור לפי תפוסה, שדה שאינו שלילי, פנייה רוחבית ופעילות תואמת לגרסה הקודמת |
| `test_field_composition.py` | החלפת רכיבים במנוע | שדה ופנייה חלופיים משנים את התוצאה הצפויה; שארית משתנה אינה נעצרת בשדה חלופי |
| `test_engine.py` | סיבתיות, תפוסה ועדכון | השדה מתקדם עד שכן אחד, חלקיק מתקדם עד שכן אחד ומתעדכן פעם אחת בצעד |
| `test_diagnostics.py` | מדידה ותצוגה | חתכי XY, XZ ו־YZ מדויקים; תצוגת XYZ שומרת את כל הקואורדינטות והתאים מחוץ למישור; מצב המקור אינו משתנה |
| `test_application.py` | הרצה ותאימות | נוצרים מטא־נתונים, אירועים ו־HTML עצמאי; תצוגת נפח ותצוגת חתך מפיקות אותם אירועים; הממשק הישן ממשיך לפעול |
| `test_regressions.py` | ההתנהגות שכבר אומתה | כל המצב והאירועים זהים לגרסה הקפואה בכל 278 צעדי ההשוואה |
| `test_architecture.py` | הפרדה בין שכבות | ייבוא משכבה אסורה או נוסחה במתאם נכשלים; כל המודולים הפיזיקליים עוברים ביקורת שלמים |

שמות הקבצים בטבלה הם מתוך `tests/`. בדיקות ההפרדה משתמשות ב־
`tests/architecture_rules.py`; גם הכללים עצמם נבדקים מול דוגמאות מותרות
ואסורות, כולל ייבוא יחסי ושמות חלופיים לייבוא.

## דוגמאות עם תוצאה צפויה מדויקת

`test_render_motion.py` בודק תצוגה בלבד: ברבע c אורך החץ 2.7 וב־c
אורכו 10.8; חץ אלכסוני בחצי c באורך 5.4. מנוחה או קנה מידה לא ידוע
אינם מציגים חץ מהירות. שינוי של אפס או צעד אחד אינו מסומן; שני צעדי
סריג ומעלה מסומנים כקפיצה בתצוגה. בדיקה נפרדת מזהה מעבר מחזורי
בשני הכיוונים ובכל הצירים לפי ממדי העולם, ומבדילה אותו מקפיצה רגילה.

| החישוב | הקלט | התוצאה הצפויה |
| --- | --- | --- |
| מקור אחיד | 3 מקורות, עוצמה 64 | 192; ללא זיכרון של פליטות קודמות |
| השדה שלנו | שכנים `(1,2,3,4,5,6)`, שני מקורות של 64, שארית קודמת 3, מכנה 7 | ערך 21 ושארית 5 |
| שדה כללי חתום | משקל ‎−1 לשכן הראשון, ערך השכן 10, מכנה 3 | ערך ‎−3 ושארית ‎−1 |
| בחירת טווח | דגימה עם ערך ‎−3 ושארית ‎−1 | מדיניות השדה שלנו מחזירה ערך 0 ושארית 0 |
| גרדיאנט | שכנים `(9,4,2,10,6,6)` | `(5,-8,0)` |
| פנייה במודל שלנו | תנע `(3,0,0)`, גרדיאנט `(128,64,0)`, מכנה 64 | דחף `(0,1,0)`, תנע חדש `(3,1,0)`, תנע שדה `(0,-1,0)` |
| דחף קטן | וקטור `(0,1,0)` בכל צעד, מונה 1, מכנה 64 | לאחר 64 צעדים מתקבלת תוספת תנע אחת בציר y והשארית חוזרת ל־0 |
| תנועה ברבע המהירות | תנע `(3,0,0)`, מגבלה 12, תקציב התחלתי 0 | תקציבים 3, 6, 9; בצעד הרביעי מעבר ל־‎+x ותקציב 0 |
| כיוון אלכסוני | תנע `(3,-2,1)`, פאזה התחלתית 0 | מחזור של ‎+x, ‎+x, ‎+x, ‎−y, ‎−y, ‎+z |
| גבול מחזורי | ממדים `(4,5,6)`, כתובת `(-1,12,13)` | כתובת `(3,2,1)` |
| שדה חלופי עם שארית | ערך התחלתי 1, משקל מקומי 8, משקלי שכנים 0, מכנה 7 | הערך נשאר 1 ושאריותיו 1 עד 6; בצעד השביעי הערך 2 והשארית 0 |
| גלישת ביניים | מכפלה שחורגת מ־64 ביט, גם אם שארית נגדית יכולה להחזירה לטווח | `OverflowError` כבר בשלב המכפלה |

הדוגמאות הן תוצאות קבועות שהבדיקות משוות אליהן. בדיקות שימור משתמשות גם
בזהויות, כגון סכום תנע החלקיק והשדה לפני העדכון ואחריו. בדיקות הרגרסיה
משוות למקור קפוא נפרד; הן אינן מעתיקות את הנוסחה הנבדקת כדי לחשב ציפייה.

## מה נמצא היכן לאחר הביקורת

חישוב המקור ואיפוס שדה שלילי נמצאים ב־`fields/policies.py`. החשבון של
השדה נמצא ב־`fields/scalar.py`; הפנייה והתנועה נמצאות ב־`dynamics/`.
הכתובות והשכנים מרוכזים ב־`core/lattice.py`. הכפלה, צבירת שארית וחלוקה
חסומות נמצאות ב־`core/state.py` ומשמשות את שלושת רכיבי הפנייה.

ההחלטה אם תא ממשיך להתעדכן מסופקת למנוע. המודל המקורי בוחר בכלל הפעילות
הקודם במפורש; שדה שמסופק דרך `Simulation(field=...)` עוקב כברירת מחדל גם
אחרי שינוי בשארית. אפשר לספק מדיניות מפורשת באמצעות `field_activity=`.

ב־`models/current_field.py`, ב־`api.py` ובקובצי התאימות אין נוסחאות חישוב
עצמאיות. בדיקת הארכיטקטורה מזהה פעולות חשבון שמתווספות אליהם. הגדרות
המודל ותנאי ההתחלה נשארים פרטניים בכוונה ונבדקים לפי ההתנהגות שהם מייצרים.
המסגרת הכללית עדיין כפופה ל־3D, לשישה שכנים ולמבנה התא הקבוע שהוגדר בפרויקט.

## איך מריצים ובודקים שינוי

מתוך הפרויקט המותקן מריצים `python tools/check.py`. הפקודה בודקת סגנון,
טיפוסים והתנהגות ומייצרת את `artifacts/test-runs.html` לכל הרצות המנוע.
בדיקות יחידה של חישוב טהור אינן מפעילות עולם. לתוצאות ההרצה האחרונות
ולגרסאות הכלים ראה `VALIDATION.md`.

בהוספת חוק חדש מגדירים מראש קלט, תוצאה צפויה ומקרה גבול; בודקים את החישוב
בנפרד ואת החיבור שלו למנוע. בדיקת המבנה אוכפת גבולות ידועים בקוד, ואינה
תחליף לבדיקת ההתנהגות של החוק החדש.

## הוראות משותפות וגבולות ארכיטקטורה

- קלט: מבנה הפרויקט וחבילת המקור. ציפייה: `AGENTS.md` קיים, מופנה מ־README,
  הוראות התרומה ומסמך הארכיטקטורה, ונכלל ב־MANIFEST.in; כל המסמכים שאליהם
  הוא מפנה קיימים. CI משתמש באותה פקודת אימות כמו העבודה המקומית.
- קלט: מודל שמייבא מנוע דרך `from ..core import engine` או `linked_engine`.
  ציפייה: בדיקת גבולות השכבות דוחה אותו, גם בצורה העקיפה הזאת.
- בדיקות אלה אינן מריצות עולם ואינן מוכיחות שסוכן בשיחה אחרת קרא את הכללים.
