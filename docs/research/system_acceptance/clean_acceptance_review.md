# Central acceptance integration review

## Decision

The collector integrates the local-source and gauge research through the
existing saved-run runtime. No additional Engine, evolving state, physical
default or production model selector is introduced. The inspected changes
have no identified software integration blocker. Completion of the final
aggregate run and published-tree checks remains a separate release condition.

## Evidence path

The local-source call uses `collect(out)` without its optional quick flag.
The default `quick=False` executes the complete registered organization panel,
not the reduced nine-case subset. That collector independently inspects the
same twelve-channel saved history for records, balances, source constraints
and finite-chart geometry. Supporting constructions remain separately named.

The gauge call executes four static histories (two flux preparations and
their complete gauge copies) and one separately identified dynamic history.
The static and dynamic laws retain their own tensor and bundle identities.
Their existing instability, period-three, carry, locality and raw-click
countercontrols remain part of the collected report.

`inspect_claimed_run` first invokes the production verifier through
`inspect_saved_run`; it does not issue a receipt from an unchecked package
summary. It then matches the claimed run, bundle and tensor identities. The
receipt additionally records the complete seed, model, protocol, channel
manifest, trace, clicks, horizon and current repository source hash. The
run identity binds the bundle and horizon; the production verifier recomputes
the complete trajectory and exact report. These hashes express compatibility
and integrity, not author authentication or independent physical validity.

The existing seven rejected-join controls are extended by four: local source
versus homogeneous source, local source versus static gauge, static versus
dynamic gauge, and two flux preparations of the same static law. Thus an
unchanged runtime does not authorize pooling different physical constructions.

The source closure is captured before the sequence and checked after all
collections. A Python source change during execution causes an explicit
failure. Evidence is written only below the caller's new output directory;
the top-level collector refuses an existing destination before research runs.
Pinned historical evidence is not overwritten.

## Physical scope retained

The aggregate report keeps general physical acceptance blocked and same-law
recurrent cosmological bursts with sustained growth unestablished. Its local
row includes actual claim statuses, including the failed global positive
periodic chart and untested massive-body/operational-clock/growth claims.
The gauge row expressly names two separate finite constructions and retains
their unestablished physical gates. `accepted_scoped` therefore describes
the bounded construction, not every physical target in its evidence row.

The full registered local organization panel is retained in the ledger.
Its failures and insufficient histories cannot be replaced by repeat-use
successes from the main demonstration. Likewise static interference and
dynamic link feedback cannot be combined into a propagating field claim.

## Independent verification

```text
python -m unittest universe24.tests.test_system_acceptance -v
```

All six tests passed. They cover same-field/different-carry rejection,
corrupted saved bytes, fresh-output refusal, indirect source provenance,
anisotropic source/metric/calibration checks, and the new summary-substitution
test. The latter accepts the genuine saved identity, rejects a distinct
complete run, and rejects alteration of each of the three required claimed
identities.

The parent aggregate run was still active during this review. This document
does not assert that it finished, nor does it substitute the focused tests
for final full-suite, complete collector or CI outcomes. No Python source
was edited for this review.
