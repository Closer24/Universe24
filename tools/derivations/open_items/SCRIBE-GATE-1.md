## What it refuses

A refusal (tier BLOCK) stops the push; a note (tier WARN) is printed and the push goes.

## How it decides: a ratchet, and no list to keep

A push may not raise the count of any hit above the same file's at its merge base (the revision named by CHECK_BASE, else origin/engine-5.0-test): what stands at the base stands, and the code departs from the law at the register's R5 until the Boss removes it. A hit is keyed by its rule, its file and its detail (the number, the name, the container), never by its line, so a moved or reformatted line is no new hit; a module git reads as renamed carries its counts; a new file has none. Replacing one hit by another of a different name is a new hit. A hit leaves the list by being removed and enters it only by the owner's word: tools/derivations/open_items/scribe_scan_allowed.json holds the entries the owner allowed (rule, file, detail, count, his word, the ledger's row), is written by Sofer alone and is read from origin/scribe-5, so that a push cannot allow itself by editing its own copy. It stands empty. **The floor:** a merge base that lies behind FLOOR (526a5666d, the engine head the list that stands was taken at) in its own history, with the tree holding FLOOR, is read as the floor, so that a pull request into main is read against the floor and not against main's older code (the first hostile review's F1: against origin/main the gate had refused 951 lines and noted 147); a merge base beside the floor, on a line the floor is not part of, stands as it is (the fourth review's follow-up); the self-test pins FLOOR to 526a5666d, so that moving it needs the owner's word and the list taken anew.

A patch (`--patch FILE --base REV`) and a push also print one line of counts by rule from the base to the push (`counts from the base: LOOP 372 to 360, CLAMP 76 to 70`), so that the plan's end check, every count falling or equal and 0 at the end, is read at each push.

## Where it runs
